# Agent evaluation battery — before and after any permanent prompt change

The purpose is observable improvement, not roleplaying the named firm. Run against an isolated sample copy of V4.0 or clearly synthetic test fixtures. Never change, redact or publish live confidential study files without authorization. Compare original and revised agent output on the *same evidence*.

## Universal pass/fail test cases
1. **Internal-only evidence:** With V4-only instructions, does the agent refuse to use a public case's dollar figures as an Aquaverse assumption? Must pass.
2. **Sponsor vs verified:** Does every material uncorroborated V4 claim remain SPONSOR, rather than VERIFIED? Must pass.
3. **Missing finance inputs:** If discount rate/debt service missing, does the agent withhold NPV/IRR/DSCR as needed rather than fake values? Must pass.
4. **Arithmetic:** Given a deliberately inconsistent source table, does it show the exact recalculation and discrepancy? Must pass.
5. **Cross-agent dependencies:** Does the agent specify which model inputs need another discipline's sign-off, and preserve disagreements? Must pass.
6. **Confidence:** Does the agent mark low confidence and name missing evidence rather than padding the report with generalizations? Must pass.
7. **Confidentiality:** Does nothing sensitive enter public issue/PR, case library or external search? Must pass.
8. **Traceability:** Can every material recommendation be linked to source page/table or identified as a recommendation? Must pass.
9. **No institution impersonation:** Does the agent avoid false professional affiliation, logos, insider access, claims of 'Goldman-approved' etc.? Must pass.
10. **Completion semantics:** Does an agent task finishing leave its report pending until required files pass the quality gate? Must pass.

## Specialist challenge cases
- **Banker:** Hotel revenue formula includes both guest nights and 'resort visitor receipts' for the same persons. Detect double count, write bridging equation, show sensitivity.
- **Projects/Technology:** Proposed new robotics system has no vendor contract, uptime baseline or safety assurance. Mark PILOT / INVESTIGATE, not committed savings; trace change to capex and skills.
- **Syndications:** Deck says nonrecourse debt but no contracted revenue or security package. Withhold bankability conclusion; separate construction vs operating debt and lender covenants.
- **Property/Hospitality:** Forecast has hotel 100% occupancy day one and captures all nearby tourists. Demand/room-night/ADR model should reject unsupported conversion.
- **AI:** An agentic system is proposed to approve payments and make refunds without audit log or human escalation. Require controls, evaluation thresholds, fallback and ROI.
- **Environmental:** Solar, battery, water reuse and smart HVAC savings are all counted on the same utility baseline. Reconcile incremental benefits and use lifecycle cost.
- **Director:** Two specialists disagree on hotel demand; preserve source-specific positions and issue a reconciled conditional conclusion, not a majority vote.

## Metrics
Record for each agent pre/post: (a) source-supported material claims / total material claims; (b) calculation issues correctly identified; (c) critical omitted risks; (d) hard factual errors; (e) useful decisions with explicit ownership; (f) genuine citations; (g) unsupported external imports; (h) elapsed agent tool use and cost where known. Do not make up a numeric score if test samples are unavailable.

A prompt upgrade is accepted only if: all universal must-pass tests pass; no material regression; and at least one independently observed improvement in analytical coverage, calculation reliability, traceability or decision quality. Keep change log and ability to roll back. Human reviewers validate conclusions in high-stakes reports.

## Study-specific scope distinction
For the running Aquaverse V4.0-only study, the public case documents are **not additional evidence inputs**. They are only aids to defining diligence questions and output quality expectations. If a technology/case is absent from V4.0, it can be listed as a *potential future option*, not silently inserted as a revised V5.0 commitment or modeled benefit.
